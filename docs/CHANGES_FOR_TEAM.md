# Changes since the LLD (backend core, branch `harsha/backend-core`)

Everything below is live in the real API and mirrored in stub mode (`app/stubs.py`). Additive fields don't break
anything built against the old examples; the items marked **Action** need a change on your side.

## For Venky (Next.js app)

**Errors and status codes**
- **Action:** every error is `{"error": {"code": "...", "message": "..."}}` at the top level, including validation
  errors (HTTP 400, code `invalid_request`; `message` is a list of field errors). Show `message` in the toast.
- Creates return **201**: `POST /api/households`, `/members`, `/helpers`, `/members/{mid}/grant`, `/absences`,
  `/topups`, `/signups`. Everything else returns 200.
- Auth failures: 403 `missing_token` / `bad_token` / `owner_only` / `own_grant_only`. Another household's IDs return
  404 `not_found` (never 403).

**Grants (needed for auto-approval)**
- **Action:** each member must grant the agent their limits: `POST /api/members/{their own member_id}/grant`. Without
  it, *every* money request goes to a vote. Show a "Grant agent limits" button when
  `dashboard.me.grant_status` is `missing` or `outdated` (outdated = terms changed or a helper was added since; granting
  again fixes it). A member can only grant for themselves.

**New fields (additive)**
- `dashboard.me.grant_status`: `active` | `outdated` | `missing`.
- `dashboard.alerts`: `[{code, message}]`, codes `low_balance`, `needs_topup`, `grant_missing`, `grant_outdated`.
  Show them as banners.
- `dashboard.open_votes[].overdue` (bool), and each `votes[]` item is `{member_id, name, decision}`.
- Helper card `grocery.budget_used_paise`: what counts toward the budget (money moved to the spending wallet + cash
  repaid). `grocery.spent_paise` is what was actually spent. Show "used X of budget" from `budget_used_paise`.
- Request objects: `votes_needed`.
- Ledger: response has `month`; each entry has `note`.
- Payroll runs: `executed_at`; `status` can be `needs_topup` (wallet too low; run payroll again after a top-up).
- `GET /api/employments/{eid}`: new `terms` object (all editable terms, for the edit form); `leave_days[].marked_by`.

**Endpoints and rules to handle**
- **Action:** demo reset is `POST /api/admin/reset-demo` with header `X-Admin-Token` (not a member token). Call it from
  a Next.js server route/action so the admin token never reaches the browser. It returns
  `{household_id, owner: {name, token, link}, roommate: {...}, helpers: [{name, whatsapp_e164, employment_id}], month}`;
  open `owner.link` afterwards (old links stop working).
- Add helper: 409 `helper_exists`; 400 `invalid_phone`, `invalid_limits` (an auto-approve limit can't exceed its
  monthly limit; the monthly advance limit must be below the salary). `payday_dom` is 1–31 (shorter months pay on their
  last day). `whatsapp_link` is `null` until `WA_BUSINESS_NUMBER` is set on the backend.
- Votes: 409 `already_voted`, `already_decided`.
- Mark absent: 400 `weekly_off`; 409 `leave_exists`.
- Run payroll: 409 `advances_exceed_pay`, `grant_missing`; 400 `future_month`. Running it twice returns the same run.
- Ledger/contributions `?month=` must be `YYYY-MM` (400 `invalid_month`).
- **Action (deploy):** add the deployed web app's origin to the backend's `WEB_ORIGIN` (comma-separated) or the
  browser will block requests (CORS).
- Stub mode is now opt-in: run the backend with `USE_STUBS=true` to get the example payloads without a database.

**Hosting (changed)**
- The backend now deploys on **Vercel** (Render web service didn't work); the database stays on Render. The API base
  URL will be `https://<project>.vercel.app`. Put the Next.js app on Vercel too and add its URL to `WEB_ORIGIN`.

**Ops**
- Backend env (now on Vercel; same names on Render): `DATABASE_URL` (Internal Database URL, as-is), `PUBLIC_BASE_URL`, `WEB_ORIGIN`,
  `WA_BUSINESS_NUMBER` (digits, e.g. `9198xxxxxxxx`), `DEMO_HELPER_E164` (the team phone playing Lakshmi).
  `TOOLS_TOKEN`, `ADMIN_TOKEN`, `WA_VERIFY_TOKEN` are generated by `render.yaml`.

**Roommates and flats (new)**
- `DELETE /api/members/{mid}` (owner): removes a roommate. Returns
  `{member_id, removed_at, final_balance_paise, month}`; show the final balance (positive = the flat owes them). Their
  link stops working at once (403), their grant is revoked, their votes on open requests are withdrawn, and open votes
  are re-settled with the remaining roommates. They still appear in this month's contributions (they settle the month
  they leave), not in later months. 403 `cannot_remove_owner`, 403 `owner_only`, 404 if already removed.
- Adding a roommate whose phone is already in the flat: 409 `member_exists`.
- **One person, several flats.** `GET /api/me` now includes
  `flats: [{household_id, household_name, member_id, role, token, link, current}]`. Show a flat switcher when there's
  more than one: switching means using that flat's `token` as `X-Roz-Token` (each link only opens its own flat).
- `POST /api/me/link` `{other_token}`: joins another flat's link to this person (the person proves they hold both
  links; a matching phone number alone never joins flats). Returns the same shape as `GET /api/me`. 404 for an
  unknown link, 409 `same_household` if both links are for the same flat. Calling it again is harmless.

## For Divyansh (WhatsApp, voice, agents)

**Tool outcomes**
- **Action:** every `create_*` / `record_cash_spend` / `execute_request` outcome is now
  `{status, template, summary_slots}`. `template` is the reply key in `app/agents/templates.py`; render
  `templates.render(outcome["template"], lang, **outcome["summary_slots"])`. Slots are ready to print: rupees as
  numbers (`500`, not paise), day counts as whole numbers when whole (`2`, not `2.0`), dates as text (`26–27 Oct`).
- Slots by template: `leave_approved` / `leave_needs_vote`: `household, dates, left` · `advance_approved` /
  `advance_needs_vote`: `household, amount, month_total` · `grocery_approved` / `grocery_needs_vote`:
  `household, amount, wallet` · `cash_recorded`: `household, amount, item` · `needs_topup`, `rejected`,
  `sent_for_approval`: `household`.
- `record_grocery_spend` returns `summary_slots: {amount, item, wallet}` (template `spend_recorded`);
  `get_balances` returns `summary_slots: {left, month_total, payday, projected}` (template `balances`).
- New template key `sent_for_approval` (requests of kind `other`, and cash spends that need a vote). `cash_recorded`
  now says the money has been repaid (it is, in the same step). Please add `kn` / `hi` for both.

**Tool behaviour**
- `get_helper_context` accepts the number with or without `+`/spaces (`919811100009` works); each household now has
  `consented`.
- `record_consent` also counts the helper as a real user on `/stats`.
- Tool errors to handle (`ok: false`, `error.code`): `no_consent` (send the consent prompt), `insufficient_funds`
  (spending wallet empty: say so), `invalid_dates`, `invalid_amount`, `leave_exists`, `not_found`, `invalid_args`,
  `already_decided`, `not_auto_approvable`, `employment_ended`, `idempotency_conflict`, `internal_error`.
- **Action:** use a stable `idempotency_key` per WhatsApp message and request (`<wa_message_id>:<index>`); a repeat
  returns the stored result and never moves money twice.

**Treasurer agent**
- `AGENT_RUNTIME` now defaults to `off`: the backend runs the treasurer steps in code. Set `local` or `agenticorg`
  when `app/agents/runtime.run_treasurer(request_id)` is ready.
- The backend calls `run_treasurer(request_id)` (async, 8 s timeout) from inside each `create_*` tool after committing
  the new request. Your agent must finish it through the tools; if it raises, times out or leaves the request
  `pending`, the backend completes it with the same rules.
- Guardrails are in code, not just the prompt: `execute_request` on a pending request re-evaluates it and refuses
  unless the rules say AUTO (`not_auto_approvable`); `open_vote` always takes `votes_needed` from the rules. Your
  `context_text` is kept in the audit log; the vote card shows a sentence built from the database.

**WhatsApp**
- **Action:** the backend runs serverless on Vercel (60 s max per request, nothing runs after the function returns).
  Do the voice-note work inside the webhook request, or in FastAPI `BackgroundTasks`, and keep the whole pipeline
  well under 60 s. Don't start threads or rely on a process staying alive.
- **Action:** `POST /webhooks/whatsapp` returns 401 unless `WA_APP_SECRET` is set (signature check).
- `/stats` shows the median of `message.latency_ms["total"]` for inbound messages; write `total` in ms.

## Database (contract 1)

- `employment.payday_dom` is 1–31 (was 1–28).
- New internal tables (migration `002`): `tool_call` (idempotency) and `agent_grant` (members' grants). No effect on
  the web or tool contracts.
- Migration `003`: `member.removed_at`, a `person` table and `member.person_id` (existing members are backfilled as
  their own person).
